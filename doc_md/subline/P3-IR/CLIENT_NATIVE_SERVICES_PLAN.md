## 实现边界

1. 原生界面复用现有覆盖层、滚动、按钮、分页、输入组件；不上嵌入浏览器，不开启旧 osu! 在线总门、聊天、presence 或多人。
2. 新端内服务覆盖层持有页面导航历史，路由使用明确 OMS ID / MD5 与玩法、键型、来源、条件、页码。历史 LR2IR 身份不能转成 OMS 个人页；未知 PP / 国家 / 等级不制造字段。
3. 公共玩家页直接复用当前个人 / 排行 API，本人私有历史仍由原窗口维护。桌面账号只走既有 Bearer 刷新链，Web cookie / Origin / Actor 保持原边界。社区明确增加桌面写入支持，继续相同作者权限、限流、输入预算和 UUID 幂等；不把浏览器 cookie 复制到客户端。
4. Web 增加公开结构化新闻 / 帮助接口，保持唯一内容源、版本、ETag 和有界缓存；不得在内容中包含账号秘密。客户端请求不携带桌面 token，拒绝跳转、限制解码体积 / 超时。
5. 页面打开 / 切筛选 / 翻页 / 主动刷新才请求。取消旧请求，迟到响应不能覆盖新页 / 新账号；隐藏和账号变化清除私有数据。返回只复用当前会话已经读取的页面，历史数量有界；无常驻轮询，不在启动预抓所有在线页。
6. 谱包直达既有批准源，OMS 服务器不代理大文件；未知来源 / 缺少原 mania MD5 关联时如实提示，不以歌名搜索冒称同谱匹配。

## 执行顺序与文件归属

1. **规划与契约**：根执行者维护本计划、Dev Bridge 的端内导航 / 内容 / 社区桌面合同；来源事实在实际实现后进入 Client Bridge。
2. **服务支持**：Backend 执行者只修改社区桌面认证与相关软件检查，不改 SQL / schema / 备份；Web 执行者只负责结构化内容、原网页共用内容与对应检查。
3. **端内公共页面**：客户端执行者负责新覆盖层的个人页 / 玩家排行 partial 及专用检查；根执行者负责导航核心、请求消费者、谱面 / 社区 / 内容、原入口接线与整合。
4. **软件与回归**：所有 build / test / formatter 由根执行者串行调度，检查时暂停源文件修改。先行为检查，再 Desktop Release / Debug 与必要的账号 / IR / 下载回归；不制造用户真实成绩或生产帖子。
5. **服务发布**：构建准确不可变 Backend / Web 包，核源与空间，固定 helper 发布前后完整备份 / F 核验，有限实际共载、公开内容 / 旧网页 / API / 双站、同库新 → 上一版 → 新往返。沿现行服务限额 / 备份约束，不刷新既有未变化的 1,800 秒 / 两空恢复历史。
6. **记录与交付**：客户端来源快照 → Client Bridge facts → Dev Bridge 采用 → Web / Backend 状态。各仓只选择本轮增量提交推送；文档 / 链接检查通过，列出实际软件 / 运行证据与真实设备 / 账号未验项。

- 当前源码编译、聚焦行为检查、必要回归和跨仓文档门通过；服务已按准确来源实际部署并有完整备份 / 同库回退证据。
