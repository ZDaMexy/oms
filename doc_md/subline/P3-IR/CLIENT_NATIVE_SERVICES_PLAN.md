# OMS 端内原生页面接续验收计划

## 目标与输入

三来源谱面浏览按当前能力完成软件与隔离桌面渲染闭环，行为、来源和验证只取[状态](DEVELOPMENT_STATUS.md)；展示能力只取[P1-A合同](../P1-A/TECHNICAL_CONSTRAINTS.md#谱面列表展示与来源能力)，共同职责取[原生合同](../../../../oms-server/dev_bridge_md/doc_md/mainline/client-native-services.md)。本页只维护尚未签收的真人体验，完成记录见[本线历史](CHANGELOG.md#2026-10-12谱面列表模式与来源分层)。提交 / 推送沿仓库现行授权边界。

按用户决定，先验已有新闻、帮助、排行、玩家、谱面与账号；聊天、好友和在线状态留到后续。用户通过 VS Code 非调试启动当前工作区，日常验收不生成 Windows 发行包。

## 谱面列表按 lazer 能力对标（2026-10-12）

用户提供 lazer 参照并授权规划至闭环，随后明确模式在先、来源归属模式：BMS → Ginger Rush / 616，osu!mania → Sayobot。对应紧凑筛选、实际普通 / 大卡、固定字体 / 窄窗、稳定标题、独立难度与任务状态、真实可选封面和原生展开 / 悬停动作已实施；错误的 OMS 目录来源、UI和列表读取已撤出，具体 MD5 详情 / 榜保持。实际能力矩阵和缺字段取上方合同，不在计划另立版本。

来源切换 / 恢复、失败重试、后台下载 / 精确打开、相关回归、两配置构建、实际渲染和独立复审均完成。本轮未签用户账号 / 实站原包 / 整曲、IME / DPI / 设备与发行；按下方真人顺序接续，不重复已通过且输入未变的软件检查。
