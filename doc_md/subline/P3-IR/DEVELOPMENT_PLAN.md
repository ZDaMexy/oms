# OMS IR 客户端与服务闭环计划

## 授权与范围

2026-10-03 用户先授权“详细规划到闭环，然后按规划开工”，随后授权“一路做下去吧，及时commit和push，直接部署就行我在真实环境验收”。独立 IR 持续实现、验证、提交、推送与生产试运行均已授权；软件与运行门通过后直接部署，再由用户完成真实游玩验收。Phase 1.x 设备、皮肤与发行门继续保留。玩家主动启用后完成：注册 / 登录 → 游玩 → 最终结算与本地保存 → 交分 → 端内和网页查同一榜；断网或会话失效后恢复补交。关闭 IR 仍可完整离线游玩。

服务与网页在现有 `F:\zdamexy-workspace` 对应项目开发。跨端唯一合同位于 `oms-server/dev_bridge_md/doc_md/subline/oms-ir/constraints.md`，完整执行计划在同目录 `dev-plan.md`。本线维护客户端接入、用户数据与验收投影，不复制外部接口正文。osu-web 固定源码已取到该工作区，只参考页面组织、行为和边界，采用独立 FastAPI / SQLite 服务。

## 闭环顺序

| 门 | 玩家 / 维护者结果 | 退出条件 |
| --- | --- | --- |
| IR0 | 成绩身份和可比较条件明确 | 提交绑定源码、事实桥登记、合同与双方采用一致；BMS / PMS 9K、最终灯、血条、判定与计分版本不混淆 |
| IR1 | 本地真实账号、交分与网页试验榜 | 同局幂等、异内容冲突、账号隔离、分组榜、最佳分 / 最佳灯、服务重启、一致备份恢复和实际浏览器路径通过 |
| IR2 | 端内主动连接、保存后交分和查榜 | 默认 endpoint 空；Windows 凭据库存令牌；新局捕捉真实玩法条件；BMS / mania 正常保存后交分，不阻塞本地结算；端内 / 网页一致 |
| IR3 | 网络失败、重启及账号切换后补交 | 持久待交绑定服务与原账号；401 保全、重登续交；响应丢失重复无新增；匿名局不自动认领；关闭或本地删除不隐式删服务端历史 |
| IR4 | 50 人规模下可维护运行 | 真实主机与代表性数据量峰值预算、延迟 / 内存、备份恢复、账号恢复、滥用处理、TLS / 配置 / 留存与回退验收，按已有授权部署试运行 |

各门独立验收，服务 fixture 不证明端内交分成功。50 人按每人约三分钟一局估算，平均约 0.278 次交分 / 秒，集中结束模型 50 局 / 10 秒；服务器约 500 MiB 新服务预算须实测。公网 100 Mbps 是峰值并按出网计费，不能代替 CPU、内存、磁盘与月费用预算。

## 真实环境验收与剩余门

1. 用户通过 VS Code 非调试启动当前工作区，主动连接 `https://oms.zdamexy.work` 并注册 / 登录；分别完整手动游玩原生 BMS 与 mania，核对最终本地成绩、端内本人记录、网页同一局和同条件榜。首轮仅正常完成并实际保存的新局，失败 / 中退手动保存、历史导入和回放播放不自动交分。
2. 开局已登录后断网，完成一局并确认本地结果；关闭、重启并恢复网络，原账号补交只生成一条。关闭 IR 继续游玩、切换账号、原账号重登和会话失效也要核对归属及本地保全。
3. 窄窗口 / DPI、中文长谱名、分页、本人记录清空及 Windows 凭据真路径补设备体验；软件已有证据见[状态](DEVELOPMENT_STATUS.md)，不重复开发同一入口。
4. 日常实机验收不触发发行打包。portable / 自定义根、覆盖组合和正式包冷启动留到用户自行构建发行时验收，已有隔离组合证据保留，不关闭 Phase 1.x 皮肤、硬件、听感和公开发行门。
5. 不支持的 Mod / 参数明确显示阻塞原因并保全待交；按真实游玩需求逐项扩大，不用 Ranked 或本地 display bucket 作为公平榜准入。首版客户端不会把本地未保存的自动演示和回放作为新局交分。
6. 服务已部署；运维按 Backend 发布文档检查日备份、外取快照、容量 / 磁盘和失败日志。同出口 50 人登录约一分钟、注册 20 人 / 小时属于当前限制；只有真实使用证明不足时再调整。
