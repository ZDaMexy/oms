# P1-D 技术约束：控制器校准与诊断

1. 校准与 diagnostics 必须建立在现有输入主链之上，不得复制第二套并行输入语义。
2. 不得把临时 debug overlay 冒充成正式 diagnostics UI。
3. 不得在未冻结行为边界前对外承诺具体控制器调校能力。
3a. 产品入口沿现有按变体的补充绑定编辑器，区分单次捕获和持续信号测试；设备发现迟到不能重建编辑行并抹去未应用修改。离线保存项仍可辨认，同型号旧绑定歧义不得自动选择第一台。
3b. 参数按实际用途显示：相对位移用设备计数，环形／摇杆模拟用圈数，位置按钮阈值用归一化行程，死区仅作用于摇杆模拟。停止等待只决定最近运动多久后松开持续状态，不延迟首次攻击；范围／中心在高级区域，不凭设备能力自动切换模式。
3c. 持续测试同时展示原始信号、解释后的触发／运动和缺失能力原因，复用真实游玩解释器与鼠标相对来源；测试不注入 gameplay，实时编辑只重建测试配置，明确应用才写入保存值。初始绝对位置不能被捕获为一次有效运动。
3d. 捕获／测试每次只有一个 UI 所有者；取消、换行、换变体和关闭撤销所有权，不同步等待驱动发现或销毁。后台任务保有待释放资源直到完成，异常明确记录，不能靠丢弃未释放资源伪造快速关闭。
3e. 鼠标轴所需高精度模式的开关必须可达，复用宿主实际 MouseHandler.UseRelativeMode 及其持久化，不自动更改玩家选择，不另建影子配置。临时捕获的释放不能把该模式改回旧值；缺少实际能力时明确说明。
4. 校准范围、诊断入口或对外说明变化时，同次更新本线实际受影响的状态、计划、约束和验证记录；仅影响全局优先级、release gate 或硬约束时向 mainline 回写摘要与链接。同步规则以 [AGENTS](../../../AGENTS.md#权威与文档) 为准，不机械刷新无变化文件。
