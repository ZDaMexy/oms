面向皮肤制作者的 **BMS 素材+ini 皮肤系统**立项（2026-06-27，大型规划非开工）。目标＝把当前"临时应付"的纯代码型 BMS 皮肤升级成像 mania 那样「放文件夹 + skin.ini 即换皮」的产品。归属 **P1-A**（皮肤边界主归属）+ 视觉面联动 P1-L。

**为什么需要**：当前 BMS 皮肤唯一 authoring 入口是写 C# `ISkin.GetDrawableComponent()`（只有开发者能做），且默认皮肤是 **100% 程序化、零位图素材**（`BmsTemporarySkinPalette` 静态色板自注"not the future direction" + `BmsPlayfieldLayoutProfile` 几何）。缺的是 mania 已有的「素材+ini 数据层」（osu legacy skin 那套：`LegacyManiaSkinConfiguration`/`Decoder`/`ConfigurationLookup`/`ManiaLegacySkinTransformer` 按文件名约定取图）。BMS 侧这四件**全无**。

**锁定决议（用户已拍板）**：
1. **范围＝仅游玩界面**（lazer 已弃非游玩皮肤，OMS 跟随）；选歌/结果/菜单不做；不移植 LR2/beatoraja 运行时（不读 .lr2skin/.luaskin/.cim），只**对齐**其键名/元素族。
2. **ini 方言＝OMS 自有**：`[Mania]`-对齐静态段（lane/note/LN/judgeline/lighting/stage/barline，键名沿用 mania 原名降迁移成本）**＋** `[Bms]` 扩展段（gauge/turntable/scratch/keyflash/bomb/cover 绿数/ghost-TD/bpm/progress，OMS 新定义，无 mania 先例）。按 keymode 分桶（5/7/9/10/14K）。**不照搬 [Mania] 段**（mania 无 gauge/turntable 等机制）。
3. **默认皮肤策略＝程序化兜底 + 参考素材皮肤**（osu Argon 范式）：程序化默认留作不可删兜底（无 skin.ini 即此）；另人工编写一份复现默认观感的 reference skin.ini（颜色/几何为主、近零位图）作 P1 验收对象兼创作者模板。**不建"代码渲染对象→PNG"导出器**（纯色块烤图＝冗余/丢可缩放/辉光烤死；纯色车道应是 `ColourColumn{lane}` 键非图）。程序化辉光类保留"引擎绘制、ini 参数化"。
4. **校验＝fail-open + 诊断，editor 更严**：加载期永不阻断（必备件内置兜底→皮肤做不出不可玩结果）、未知键忽略+告警(前向兼容)、缺素材回退+告警；编辑期暴露必备槽+阻止保存破损。**必备/推荐/可选三档**（必备＝playfield/lane/note/LN头身/判定线/判定显示/gauge/combo）。keymode 可只声明子集、未声明回退默认。
5. **编辑生态（本轮）＝手改 ini + 热重载 ＋ 复用 lazer 布局编辑器**；完整可视化皮肤编辑器后置。
6. **布局编辑器边界＝决议 X**：布局编辑器只摆 `ISerialisableDrawable` 全局 HUD 件（key counter/song progress/计分/判定计数），**看不见 BMS 程序化件**（车道/音符/gauge/combo，见 [[reference_bms_skin_editor]]）；gauge/combo/clear lamp **保持 `DefaultBmsHudLayoutDisplay` 代码编排 + ini 调外观**，不升格为编辑器可拖摆（Y 后置）。两个编辑面正交：ini=长相、布局编辑器=摆位。
7. **架构接线**：新 `BmsAssetSkin`(读文件夹+ini) 作为被现有 `BmsSkinTransformer` 包裹的 `ISkin` 注入，**零改现有 lookup 契约**（最稳的那层＝lookup 类型/组件边界/fallback 粒度已就位，asset 层塞在其下）。

**分期（归 P1-A，用 F 系列标号）**：F0＝冻结组件契约+ini schema 草案+必备分档（纯文档）；F1＝`BmsAssetSkin`+解码器+校验器+热重载，覆盖①类静态件，产出参考皮肤（验收）；F2＝②类引擎驱动件补挂点(keyflash/explosion/bomb/turntable/ghost…，ini 仅供素材)；F3＝③类 `[Bms]` 扩展段独有件+契约冻结。
