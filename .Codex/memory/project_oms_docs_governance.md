# 文档治理召回

权威：[AGENTS](../../AGENTS.md) 管协作，[文档入口](../../doc_md/README.md) 管职责、预算和同步；当前状态只从 owning STATUS 读取。

- **绿检查不代表语义正确**：行数和链接通过仍可能把五轮测试塞进长行，或把已批准目标当作已实现。分别核对当前事实、合同、历史证据；不要让 memory 成为第二套进度表。
- **新增段落不能替代就地同步**：TOTAL曾已写入页首，主线仍称旧皮肤提交是最新产品基线，子线“最近一次验证”仍只列更早全绿结果。同步时同时核对基线、唯一验证章节、路由与失败owning待办；其它产品面的验证日期不随之刷新。
- **主合同和消费者也要同步**：状态与叶子记忆已正确，主合同仍可能写难度表必须重进/重启、谱库失效恢复或单轨筛选未完成；PLAN 删除手动 LN 接入待办后，CONSTRAINTS 邻近引言仍可能保留。IR 专章已落也不代表顶部冻结、成绩/GAS、三语首页与发行口径同步；逐项区分独立按需例外、旧在线链和实际 Mod 接收。按行为检索主约束、子线合同、消费者与记忆，不只核 STATUS；历史日期记录保留原义，不全库替换旧术语。
- **新证据不能困在单线**：10 月 3 日 IR 候选已有载荷/同包隔离启动结果，发行入口仍曾称最新为 9 月 12 日。按制品清单、原日期结果和清理记录回链 owning 状态；程序已删除不取消已发生验证，也不表示仍有可运行包。同包启动不证明跨版本、Windows Shell 解包、真实下载、新作者演练或真人游玩，分别保持剩余门，不为修正文档重打包。
- **当前入口也会比历史晚更新**：canonical 接管后曾遗留旧链底说明；中文首页更新单内置与编辑路径时，英日首页仍并列双包、暂停两包修改。2026-10-01 文档健康基线全绿，三语首页却仍把 BGA 空间不足自动搬位写成通用行为，漏分默认兼容布局与明确作者窗口；手册迁入发行套件后，也须核对引用是否直接进入随包正文。同步检查每种语言的同名章节、发布复制清单和当前操作说明，不只确认仓库链接有效。历史暂停与旧会话 push 授权不能带入新任务。
- **历史网络失败不能写成持续故障**：Sayobot已有日期的安全连接失败曾被三语首页与当前入口写成“当前节点失败”。保留最近留存实站验收日期和未签收门，历史报告回链当前STATUS；没有新网络取证时不推断故障仍在，也不能把软件/素材成功改记为真实包成功。网络错误的旧证据不随文档核对日期更新。
- **旧验收步骤可能失去入口**：移除外部工作区后，三源矩阵仍包含注册/改名/注销。集中清单更新了，`Build-Acceptance.ps1` 原样复制的 README/CHECKLIST 也可能仍要求不可达操作。核对实际复制清单，保留原范围和 legacy 输入，标明当前固定目录/刷新路径与“未执行”格；不能改数据库补前提、恢复旧入口或用后端结果代签。发行线同时承接下载窄例外与全部后续组合门，不能只说旧 ZIP 缺新外观或笼统写“所有谱面下载已隐藏”。
- **旧子线规则不能制造机械同步**：部分约束仍要求任何小改都抄写主线，或纯文档也跑 Release。按现行 AGENTS 与主线验收矩阵纠正这些残留；治理没有产品改动就不刷新产品验证日期，无状态变化的文件也不机械改日期。
- **压缩不能丢失原因**：memory 保留反直觉条件、复现线索和处理依据；重复字段/合同、旧数字和逐切过程回到源码/CONSTRAINTS/CHANGELOG。不能只把长行拆开冒充精简。
- **标题不是纯排版**：已有片段链接依赖标题。标题改名后必须检查同页、跨文件链接；fenced code 中的 `###` 曾被误判为验证子章节，合法代码不应迁就错误检查器。旧检查曾只确认文件存在，漏掉 SKINNING 章节改名后的死锚；现在本地片段检查与独立正反 fixture 覆盖该问题。
- **选择性提交也要查引用闭合**：工作区全绿曾依赖尚未提交的导航、删除和本地验收页；核对实际暂存的文档及所引源码，避免推送后复现重复入口或断链。临时核验副本漏带已跟踪的非 Markdown 链接目标也会误报，先核原件与暂存身份，保留失败，不用空文件伪造通过。
- **公开示例不等于私有证据**：公开 checksum、通用路径和合法数字矩阵不能靠模糊 regex 强迫删除；生产数据库的精确取证值只保存在仓库外。
- **可执行例子也受进程边界约束**：AGENTS 与构建记忆已写每个新 shell 加载开发存储，三语首页、发行和验收重建代码块仍可能漏掉。按真实命令检查，不能把前一工具进程环境视为仍有效；仓库开发入口与随包普通作者/玩家命令须区分，不要求发行套件携带开发脚本。

检查命令和规则不在此重复；新问题只有具备真实漏检/误报证据时才扩展检查器，避免把文档维护变成审批流程。
