BMS song-select **preview audio plays at the start of gameplay** (both autoplay and normal play). Reported 2026-06-23 via Lyrith `Stella/st4/.../​_7INSANE.bms`. Fixed (code+tests) and **user-confirmed in-app 2026-06-23** (autoplay + normal start of previously-affected songs no longer leak the preview, no anomalies). Owned by P1-J (STATUS open item ④, now closed).

**Root cause** — BMS gameplay audio is *entirely* keysound-driven: `BmsBeatmapConverter` turns every object into a `BmsBgmEvent`/`BmsHitObject`/`BmsHoldNote` carrying `KeysoundSample`, and **never references `Metadata.AudioFile`**. But `BmsFolderImporter.createBeatmapSet` sets `Metadata.AudioFile` to a *song-select preview source*: `detectFullMusicFile` (largest ≥1MB audio NOT referenced by any `#WAV` keysound) `?? resolvePreviewFile` (the `#PREVIEW` header file). `_7INSANE.bms` has **no `#PREVIEW`** but ships `_preview.wav` (3.8MB, unreferenced) → `detectFullMusicFile` picks it as "full music". Song-select: `MusicController` plays `working.Track` (= that file) = the intended preview. Gameplay: `MasterGameplayClockContainer` *also* uses `working.Track` as clock source and plays it from 0 → preview heard over the keysounds. Hits **all four**: bms-mode + converted-mania (beatmap keeps `Ruleset==bms`), autoplay (`ReplayPlayer`) + normal (`BmsSoloPlayer`) — both go through `Player`→MGCC. (Framework `Video`/BGA has no audio track, ruled out.)

**Fix = MUTE, do NOT swap the clock source.** New core virtual `Ruleset.PlayBeatmapTrackDuringGameplay` (default `true`; `BmsRuleset` overrides `false`). `MasterGameplayClockContainer` keeps `working.Track` as the gameplay clock source (timing/DT-HT/pause-resume-seek all unchanged), and when the ruleset opts out adds a `Volume=0` adjustment in `addAdjustmentsToTrack` / removes it in `removeAdjustmentsFromTrack`. **Order red line:** the mute must be added *after* `musicController.ResetTrackAdjustments()` (which clears all Volume adjustments) or it gets wiped. Removal on cleanup restores the shared preview track to audible for song-select. Gate reads the beatmap's **native** ruleset via `working.BeatmapInfo.Ruleset.CreateInstance().PlayBeatmapTrackDuringGameplay` (fail-open=play on resolve error) → catches bms-mode + converted-mania, leaves native mania/.osu playing their track.

**★ Landmine — the virtual-track / source-swap approach was tried twice and reverted; do NOT reintroduce it.** Swapping the MGCC source to a `TrackVirtual`: (a) **breaks `TestSceneBmsPlayerAudioSemantics`'s deterministic time-driving** — those tests advance the `ManualClock` backing `working.Track` (`advanceReferenceClockBy`) to drive the gameplay clock; with a real-time virtual source that control is lost (this is what flagged my first attempt — the two tests timed out). (b) Was previously found **ineffective in the real coupled clock**: swapping doesn't *stop* the original `working.Track` (still started/playing), and the virtual-track unit test was a false positive. Muting targets the track that actually plays, so it works regardless of who started it. See [[reference_song_select_perf]] discipline of trusting real signals over green unit tests.

**Tests/verify:** `TestSceneBmsGameplayTrackMuting` (BMS `working.Track.AggregateVolume==0`, standard ruleset `==1`; lives in BMS test project, uses osu.Game's in-assembly `OsuTestScene`/`ClockBackedTestWorkingBeatmap`); `TestSceneBmsPlayerAudioSemantics` 2 unchanged & green (proves clock source unchanged). BMS **957/957**, Release 0/0. Note: `osu.Game.Tests/Gameplay/TestSceneMasterGameplayClockContainer.cs` is `<Compile Remove>`d in OMS (depends on removed OsuRuleset) — can't host the core test there.

**Follow-up 2026-06-23 — song-select preview policy tightened (user request "only #PREVIEW plays, from start; everything else no preview").** `BmsFolderImporter` now sets `Metadata.AudioFile` **only** from the `#PREVIEW` header (`resolvePreviewFile`) and sets `Metadata.PreviewTime = 0` (so `PrepareTrackForPreview` uses RestartPoint 0 = plays from the file's start, not the 40%-of-length default). The `detectFullMusicFile` heuristic (≥1MB unreferenced audio → AudioFile) was **removed** along with its `allKeysoundFiles` exclusion-set building. Consequences: charts WITHOUT `#PREVIEW` (incl. the Lyrith `_7INSANE.bms` that triggered the original bug — it has `_preview.wav` but no `#PREVIEW`) now get **no song-select preview and an empty AudioFile** → virtual silent track in both song-select and gameplay (the mute fix above is moot for them but still applies to `#PREVIEW` charts). Both changes coexist: mute keeps `#PREVIEW` charts silent in gameplay; this policy limits which charts have preview at all. Preview point mechanism: `WorkingBeatmap.PrepareTrackForPreview` sets `Track.RestartPoint = Metadata.PreviewTime` (default `-1` → 40% fallback; BMS now forces 0); song-select plays via `MusicController` (`Play(restart)`→`RestartAsync()` seeks RestartPoint), looping, with a `DuckMomentarily` fade-in.

**Existing library backfill** (the import change above is import-time only, so already-imported charts keep old metadata): `BmsPreviewAudioBackfill` (modeled on [[reference_bms_composition_filter]]'s `BmsChartFilterStatsBackfill`) runs from `BmsRuleset.OnSongSelectSetup`, background `Task`. Candidates = BMS beatmaps with a **non-empty** `AudioFile` (empty already matches policy → skipped). Design (after the first-cut every-launch version dropped FPS — see below): **single Realm read** snapshots candidates into plain structs (id/path/fsPath/isExternal/audioFile/previewTime) so the decode loop touches NO Realm (only batched writes do); per candidate read `.bms` off disk (managed→`gameStorage.GetStorageForDirectory`, external→`NativeStorage`, like `computeStatsDirect`), decode `#PREVIEW`, resolve against folder via a Storage-based mirror of `resolveReferencedFile` (alt audio exts via `Storage.Exists`); rewrite `AudioFile`/`PreviewTime` (batched 200/txn, injected RealmAccess) only if changed. **One-time via a completion marker file** (`bms-preview-audio-backfill-v1.marker` in storage; checked in Initialise → skip entirely if present, written after the Task; bump suffix to re-run). **Progress notification** (`ProgressNotification` posted to INotificationOverlay, begin/update/complete, like chart-filter-stats) — first-launch run shows "正在更新 BMS 选歌预览…X/Y" (user-facing term is 预览/preview, not 试听). Crash mid-run → marker absent → resumes next launch (idempotent). ⚠️ **First-cut bug (fixed same day):** the initial version had NO marker (ran every launch) + per-candidate `realm.Run(Find+Detach)` → re-decoded all AudioFile charts every song-select entry on a 57k library = sustained frame drop (user-reported, log showed no `[BmsPreviewAudio] done` in 33s = still grinding). Fix = marker (one-time) + struct snapshot (one read) + notification. Test seam `RunForTesting`. Tests: `BmsPreviewAudioBackfillTest` (4: import sets preview-from-#PREVIEW+PreviewTime0 / import sets none when absent even with a 2MB file / backfill corrects stale preview chart / backfill clears AudioFile for no-#PREVIEW). BMS 961/961.
